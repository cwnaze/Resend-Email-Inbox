## Codebase Patterns
- This SvelteKit toolchain (current `sv create` output, kit ^2.63) configures the Vite plugin and adapter directly in `vite.config.ts` — there is no `svelte.config.js`. Adapter/compiler options go there instead.
- `@sveltejs/adapter-vercel` runtime auto-detection rejects Node versions outside 20/22/24; pass an explicit `runtime` (e.g. `'nodejs22.x'`) to the adapter if the build/dev machine runs a newer Node.
- `.prettierignore` excludes `/tasks/`, `/agents/`, and `/docs/demos/` (PRDs, agent process files, and showboat demo logs) from the app's lint/format scope.
- When writing showboat `exec` blocks meant to be reproducible via `showboat verify`, strip timestamps/durations/PIDs from captured command output (grep/sed) before showboat records it.
- A verification script that writes rows to the live DB must delete its own prior-run rows *before* asserting, not only after: otherwise idempotent ingestion answers the first call as a duplicate and every assertion silently describes what an older run wrote. Delete children before parents — the libSQL connection these scripts open does enforce the FKs.
- Real secrets (Turso URL/token, etc.) live only in the gitignored root `.env`; `.env.example` tracks variable names with empty values. Never let `showboat exec` capture raw `.env` contents or a connection string into a committed demo doc — pipe drizzle-kit/db output through `grep -v`/`sed` to redact if needed, and grep the demo file for secret-shaped strings before committing.
- Drizzle/Turso: `db` client lives at `src/lib/server/db/index.ts` (server-only import), schema at `src/lib/server/db/schema.ts`, config at root `drizzle.config.ts` (`dialect: 'turso'`). `npm run db:push` applies schema directly (no migration files generated); use `npm run db:generate` if versioned SQL migrations are ever needed.
- R2/Cloudflare object storage is private in this project — no `R2_PUBLIC_URL_BASE`/custom domain. Any story that needs to let the browser fetch/download an R2 object must call `getR2SignedDownloadUrl` (in `src/lib/server/r2/index.ts`) on demand; never assume a stored permanent public URL exists. `tasks/*.md` and `agents/prd.json` wording has been updated repo-wide to say "presigned URL" instead of "public URL" for attachments.
- SvelteKit's `$env/dynamic/private` only resolves inside a Vite/SvelteKit runtime — a standalone `tsx`/`node` script can't `import` app modules that pull in `$env/*`. For one-off infra smoke tests (e.g. `src/lib/server/r2/verify.mts`), read `process.env` directly and run via `node --env-file=.env node_modules/.bin/tsx <script>` instead.
- This repo has no linked Vercel project (no `vercel` CLI, `.vercel/project.json` absent) — any acceptance criterion requiring env vars "in Vercel project settings" can only be verified/set by the project owner; note it as an outstanding manual step rather than blocking `passes: true` on it.
- Tailwind v4 in this project uses CSS-first `@theme` config (no `tailwind.config.js`) inside `src/routes/layout.css`. Dark/light palette theming needs two distinct variable namespaces: raw per-theme values as `--dt-*` custom properties (overridden per theme selector), and `@theme`'s own `--color-*` keys pointing at them via `var(--dt-*)` — naming a `@theme` key the same as its own raw value (e.g. `--color-background: var(--color-background)`) is a self-reference and becomes CSS-invalid.
- `npm run build` actually imports every `+server.ts`/`+page.server.ts` route module during SvelteKit's postbuild analysis step (to detect exported HTTP methods) — a module that throws at import time if an env var is missing (the fail-fast pattern used by `db`, `r2`, and now `email/resend`) will crash `npm run build`, not just `npm run dev`. Any such module needs at least a placeholder value for its required env vars in `.env`, even if the real credential/account isn't provisioned yet in this dev environment.
- For an endpoint that both rate-limits and has an external side effect (DB write, third-party API call), check the rate limit first and return early (429) before doing any write/send — this keeps a rate-limited request from leaving side effects, and keeps the rate-limit path itself deterministic/testable without touching the external API.

- Webhook/signature verification covers the *raw* request bytes: never `request.json()` a signed request before verifying (a `Request` body reads once, and a re-serialized parse won't match). Read text, verify, then parse.
- For any verify-then-act boundary, return a *discriminated* result where the payload exists only on the success branch (`{ ok: true, payload } | { ok: false, reason }`) — that makes "acted on unverified data" a type error rather than a review question.
- Failure detail from an auth/signature check goes to the server log, never the response body: the client gets a bare status. A reason string handed to an unauthenticated caller is a forging aid.
- A provider's webhook payload is a *claim about* an email, not the email. Before writing a parser, fetch one real payload from the provider (their list/get API often lets you do this without waiting for a live delivery) — Resend's `email.received` turned out to carry metadata only, which no amount of reading the PRD would have revealed.
- Status codes at a webhook endpoint encode retry semantics: `200` for verified-but-unusable payloads (nothing to retry), `5xx` only for transient failures (fetch/DB). Inverting them either loses mail silently or creates an infinite redelivery loop.
- For an idempotent upsert under concurrent redelivery, `insert(...).onConflictDoNothing().returning()` + a re-read on the empty result is the pattern — a bare insert turns a lost race into a 500, which the provider then retries forever.
- Normalize the case of any value covered by a SQLite unique index at the write boundary (SQLite's `unique` is case-sensitive); compare with `lower()` on reads so rows written before the normalization existed still match.
- Idempotence on a natural key is worth enforcing twice: a cheap read up front so the happy path never creates dependent rows it has to undo, plus the unique index underneath as the authority for a genuine concurrent race (undo the dependent row when the index wins).
- Sanitize untrusted markup on the write path, so the stored column carries the safety invariant and no renderer can forget to re-sanitize.
- Pick one row per parent with a correlated subquery in the join condition rather than a second query per row: `innerJoin(child, eq(child.id, sql`(select ... limit 1)`))` keeps a list view to one query, and the INNER join then also expresses "parents with no visible child are excluded" — one rule instead of two that can drift.
- Browser-verifying anything behind an httpOnly session cookie: seed the credential row, then call the real login endpoint with `fetch` **from inside the page**, so the browser applies its `Set-Cookie`. `document.cookie` cannot set an httpOnly cookie.
- A showboat `exec` block that needs a running dev server plus a secret should be self-contained — export a throwaway secret inline, start the server with it in the environment, `trap`-kill on exit — so `showboat verify` doesn't depend on the gitignored `.env`.
- Ingestion side effects that are *best-effort* (attachment download/upload) must be swallowed and logged, not thrown: the email row is already committed and the provider's redelivery short-circuits on the duplicate check, so a throw is an unrepairable retry loop.
- Inject env-reading provider clients (Resend, R2) as a `deps` object into pure-ish server modules instead of importing them — that's what keeps those modules exercisable from a standalone `tsx` verification script with stubs.
- Never let a sender-supplied filename decide an object-storage key or a path: derive the key from the provider's own id and use the filename only as a slugified, single-path-segment suffix.
- A denormalized aggregate flag ("all children are X") must be **recomputed** from the children when it's updated, not assigned the value the caller expects — a concurrent insert between the child update and the parent update is exactly the case a blind assignment loses.
- SvelteKit's app-wide `data-sveltekit-preload-data="hover"` (set in `app.html`) runs a link's `load` on hover, so any load with a side effect needs the link to opt down to `tap` — or the mutation moved to a form action.
- One shared helper should build every query string a page's URL state uses (each control edits its own param, copies the rest) — that's what makes two independent view states representable at once, and it can't be retrofitted onto call sites that assemble `?a=…&b=…` by hand.
- User input that reaches a SQL `LIKE` needs both wildcard escaping (`%`/`_`/the escape char, with an explicit `escape` clause) and an empty-string guard: `%%` matches every row, so an "active" filter silently shows everything.
- Narrowing a capped list (search/filter) belongs in the query, before the `limit` — a post-filter in JS searches one page, not the data set.
- A `+layout.server.ts` load runs *in parallel* with the `+page.server.ts` load it wraps, so a layout that renders data a page load mutates shows a pre-mutation snapshot. Persistent list/detail shells need the mutation moved to a form action (or an explicit invalidation) before the layout can hold the list.
- Derive a view's presentation strings (snippets, plain-text bodies, formatted timestamps) in the server load, not the component: it keeps large source columns off the wire, and it's what lets a standalone script assert on exactly what the page renders.
- `svelte/no-unused-props` rejects a *declared field* the component never reads, not just an unused prop — a child's props type has to be narrower than the parent's row shape when the parent uses a field (e.g. an `#each` key) the child doesn't.
- A SvelteKit **form action runs before every `load`**, including the route group's layout `load`. So a layout that redirects unauthenticated users protects page *renders* only — an action under it must call `validateSession` itself or an anonymous POST completes the mutation and is redirected to `/login` afterwards. Anything mutating added under `(app)/` checks the session itself.
- An action that answers a non-`use:enhance`d form should `redirect(303, …)` rather than return data: without it the reader is left on the action's own POST URL (`?/theAction` in the address bar, a refresh re-submitting the mutation).
- A denormalized aggregate that more than one mutation can change ("all children are X") gets **one** recompute helper both mutations call — `markThreadRead` and `softDeleteThreadEmail` share `recomputeThreadIsRead`, because two copies of the same `not exists` are two things to keep in step.
- A destructive mutation keyed by a child id takes the **parent** id too and puts it in the `where`, not just in a lookup: holding a child id is not permission to act on it through another parent's URL. Make "wrong parent", "unknown id" and "already gone" one indistinguishable answer, and make the mutation idempotent — a double-submitted form must not 404 for something the owner really did delete.
- An **inline edit form in a list** belongs in the URL (`?edit=<id>`), not in component state: the edit affordance stays a plain link, the form is server-rendered (works with JS off, survives a refresh), and a `fail()` can re-render with the form still open. It only holds if the form's action carries the param too (`?/rename&edit=<id>`) — a form action's query replaces the page's.
- A `fail()` payload for a *per-row* form must carry the row id **and the rejected input**, and the page must apply both only to the matching row. The id stops one row's error annotating every open form; the input is what makes keeping the form open worth anything — re-seeding the field from the stored value means "correct it and save again" is retyping from scratch. Prefer the submitted value with `??`, not `||`: a submitted empty string is a real answer.
- Seed an edit field from the **stored** column, never from the load's derived display value: `displayName`'s "fall back to the address" is a rendering, and pre-filling with it turns "this has no name" into "this is named after its own address" on the first save.
- A flag that *protects* a value from being overwritten by an automated path (`auto_created`) has to be cleared in the **same statement** that writes the value. Splitting them leaves a window — and a manual edit that doesn't clear it looks like it worked and silently reverts on the next ingest. Assert the pair (edit → run the automated path → value survives), not the write alone.

  - `sandbox` without `allow-popups`/`allow-top-navigation` does **not** stop a frame navigating *itself*.   - Cross-realm `instanceof` is a trap: `event.target instanceof Element` is always **false** for nodes inside an iframe (different realm), so such a guard silently disables the handler it appears to protect. Duck-type instead.
  - Sizing an iframe to its content: measure the **body** box, not `documentElement.scrollHeight` (viewport-floored, so it only ratchets up), and give the body `display: flow-root` or the last child's bottom margin collapses through it and the final line is clipped.
  - An `onload` handler is not enough for an SSR'd iframe: the document can finish loading before hydration attaches the listener, and `load` fires once. Also measure from an `$effect` when `readyState === 'complete'`.
  - A backtick inside a comment **within a template literal** terminates the string — it produced a Vite parse error and a 500 that `npm run check` caught only after the browser did. Don't use backticks in CSS/JS comments inside template literals.
  - DOMPurify hooks are global to the singleton and `removeHook(entryPoint)` pops the last hook. Prefer `RETURN_DOM_FRAGMENT` + a DOM walk over hooks for per-call rewriting; it is byte-identical to string mode and has no shared state.
  - Prefer HTML over text for *rendering*, but only when the HTML has something visible — and count images, not just text. Every direction of this choice can lose the message: mail ships HTML that is only a spacer and a pixel, and mail ships HTML that is only a hero image with a "view in browser" text stub. A first fix for one created the other, and a third shape (nothing visible, no text part) needed the explicit "no body" line.
  - **Don't tighten a shared sanitizer to make a read-path walk easier.** Forbidding a tag on the write path is irreversible and `body_html` is the only copy; DOMPurify's `FORBID_CONTENTS` means forbidding a container *deletes its text*. Scope such a change to the path that needs it.
  - **A "cleverer" regex is a performance liability, not just a correctness one.** Skipping quoted sections needs an alternation whose branches can match the same text, which is the classic catastrophic-backtracking shape. Before replacing a regex that runs per-row, time it on adversarial *repetition* (`'<'.repeat(n)`), not just on long benign strings — I tested the benign shapes, published "no ReDoS", and was wrong.
  - When a heuristic can't be airtight, **don't let it make destructive choices.** Four rounds were spent tuning a tracking-pixel test that decided whether to discard a message's text part; every threshold had a one-attribute bypass. The fix was not a better threshold but a smaller job for the heuristic: it now decides only whether to *show* something extra, never whether to *hide* something. If a rule can be wrong, arrange for being wrong to be recoverable — show both, not the one you guessed.
- Seventh round found three more, two of them holes in round six's own rewrite:
  - **`[hidden]` is not the only element that renders nothing.** A `<dialog>` without `open` and a `<datalist>` both survive sanitization and draw nothing, so `<dialog>Full invoice text</dialog>` counted as "visible text", suppressed a readable `text/plain` part, and left the reader an empty frame — the exact failure class the rewrite existed to eliminate. `isNonRendering` now covers all three.
  - **Gating the frame on `blockedImageCount > 0` was wrong**: a body whose only image is a declared 1×1 tracker mounted a blank frame captioned "1 remote image blocked" with a button whose only possible effect was firing the beacon. The gate is now `hasVisibleText || hasLoadableImage`, where an image disqualifies itself by *declaring* a pixel size; an undeclared size stays ambiguous so the reader still decides. Hidden images are parked but no longer counted, because the count is a claim made to the reader.
  - Frame-plus-text rendered the same message twice with nothing separating them. The text is now a collapsed "Plain-text version" `<details>`.
  - **Pre-existing bug found while probing, NOT fixed here (out of scope, worth a story):** DOMPurify throws `Maximum call stack size exceeded` on a body nested ~2500 elements deep, in both string and fragment modes. On the *write* path that makes `sanitizeEmailHtml` throw inside `storeInboundEmail`, so the inbound webhook answers 500 — and per this repo's own status-code contract Resend then retries a permanent condition forever. A malformed or malicious deeply-nested email would loop indefinitely. The read path is safe by consequence (such a body can never be stored), and `prepareEmailHtml`'s recursive text walk handles every depth DOMPurify can actually build (verified to 2000). Fixing it means catching the sanitizer's throw in the inbound path and classifying it as permanent (200 + warn), the way `fetchReceivedEmail`'s 4xx already is.
  - Two independent booleans beat one overloaded verdict. "Is there anything to frame?" and "does the HTML have real text?" are different questions with different consequences; collapsing them into "use HTML or text?" is what made every fix open a new hole.
  - `textContent` is not "what renders" — `[hidden]`, and anything the sanitizer keeps but the UA hides, still contributes text.
  - **Never derive a fact about an element from a pattern match over serialized markup when the element is in hand.** This one mistake produced four separate bugs across two rounds, because the sender controls both the URL and the attribute text of an `<img>`: `?height=2` in a CDN link satisfied a "is this a tracking pixel" test, and a `>` in a query string ended a tag early and leaked `2">` as body text. In the DOM, attributes are attributes and `textContent` is text.
  - When a heuristic asks "is this real content?", require **positive evidence** rather than treating unknown as yes. "No declared size" describes a tracking pixel far more often than a hero image, and the cost of guessing wrong was a message with no way to reach it.
  - Check "can this even render?" before "is it big enough to matter?": an `<img>` with no `src` (because the sanitizer removed a `javascript:` one) is not content, whatever its declared dimensions say.
  - Earlier stories' demos (`US-F03`, `US-F04`, `US-G01`) already fail `showboat verify` on `main`, because they pin the repo-wide file count and the shared verify script's check total. Only the current story's demo is expected to reproduce — don't "fix" an old demo by rewriting its recorded history.
  - A test can pass for the wrong reason and hide the case it names: a fixture using `&nbsp;` as a "hidden preheader" decoded to whitespace, so it asserted "no visible text" without ever exercising a preheader. When a check encodes a real-world shape, use the real shape.
  - Never glob-delete generated demo assets: `rm docs/demos/*-2026-07-28.png` in a rebuild script silently destroyed the screenshots of US-F02/F03/F04/G01 (restored from `main`). Delete only the images the doc being rebuilt actually references.
  - A `querySelectorAll` walk over sanitized markup is not exhaustive — `<template>`, and anything else holding a separate `DocumentFragment`, is invisible to it. Forbid such containers rather than remembering to recurse.
  - rodney gotchas that cost real time: a link click opens a new tab that **takes focus**, so subsequent `rodney js` runs against the wrong page (re-select the app tab by URL, not by index); `rodney click` on a control that triggers a remote image fetch can hang waiting for network idle (use `rodney js "...click()"`); and clicking a Svelte control right after navigation can be a no-op until hydration (poll for a hydration-dependent value first).
